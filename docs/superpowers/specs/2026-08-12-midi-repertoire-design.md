# 把真实交响乐 MIDI 接进考试与指挥体验

2026-08-12

## 要解决的问题

`assets/repertoire/` 下已有两份公有领域交响乐 MIDI，但后端**只有导出没有导入**
（`midi_out.py`），读不了它们。目标是让这两首能用本机全部四条可运行的播放路
正确播放：`fluidsynth`（2.5.7，已装）、`sf2`（内置采样器 + `orchestral.sf2`）、
`builtin`（纯 Python 合成）、以及 `/api/practice/{id}/midi` 下载原始 `.mid`。

并在界面上可选：考试页能选这首真实乐曲或现有三首合成考卷；文件页能选内置曲目
或自己已有的项目。

## 选段：各取 45 秒

全长 7–8 分钟，在默认渲染器（sf2）上首次渲染要 9–11 分钟，且指挥 7 分钟做一张
考卷不现实。

**最终定的是 45 秒，不是最初写的 90 秒**（M7l1 改）。90 秒那版首次点开在 sf2 上
要等 15 / 88 秒，等待时间和选段长度基本成正比；而一次考试打 90 秒本身也太长。

| 曲目 | 窗口 | 长度 | 依据 |
|---|---|---|---|
| 贝七 第二乐章 | **第 51–76 小节**（tick 38400 起） | 45.8 秒 | 51 是小提琴 I 接过主题的结构分界；67 加木管、73 加长笛与圆号、75 全奏。织体 5 → 12 个声部 |
| 埃格蒙特序曲 | **tick 407808 → 结尾**（尾声最后 28 小节） | 45.8 秒 | 一路推到真正的终止和弦，不淡出。起点那一小节只有长号与两把小提琴，是乐句之间的缝 |

贝七原本取的是**开头 50 小节**，那是选错了：那一段最多只有四个声部（第 1 小节
一个木管和弦，第 3 小节起是中提琴/大提琴/低音提琴的主题，第 27 小节小提琴 II
加进来），**全奏要到第 75 小节才出现**。「织体一层层涨到全奏」这句话对旧窗口
根本不成立，反推出来的力度曲线也只是音符密度的抖动。换到 51–76 之后曲线从
0.18 一路爬到 0.90，是真的渐强。

埃格蒙特没有数拍小节，所以起点特意落在那道缝上：指挥有一小节的时间把速度立
起来，比从全奏冷启动好得多。

截取窗口的起点用 **tick** 给，不用小节号。小节号在多拍号文件里不成立：埃格蒙特
前面是 3/2 与 3/4，尾声那段 4/4 的起点除以 4/4 的小节长度是 **232.5** —— 照
小节号截会从半个小节中间切进去，强拍整段错到第 3 拍上，而音频听起来只是「怪」，
很难看出错在哪。这是实现时才发现的。

**这两段各自都是单速度、单拍号**，这不是巧合而是选段依据之一：埃格蒙特的尾声
起于 `4/4 + 152 BPM` 那个双重变更点，往前挪一点就跨进 3/4 段。因此现有
blueprint 的单速度模型原样装得下，不需要把速度图烘焙成绝对秒数那类变通，
两首也都因此能有**真实的指挥拍网格**。

选段长度进了 `self_check()`（必须落在 35–50 秒）：窗口是很容易被顺手改宽的，
而首次渲染的等待时间和它成正比。

## 架构

### 新模块 `backend/midi_in.py`

唯一职责：**SMF + 截取窗口 → 项目现有的 `(blueprint, parts)`**。

- **自带最小 SMF 解析器，不引入 mido。** `requirements.txt` 现在只有 4 个依赖，
  而这里只需要读 note on/off、set_tempo、time_signature 三种事件。
- **不走 `score.validate_and_repair_part`。** 那个函数是给语言模型输出兜底的：
  拍位量化到 1/4 拍、丢重叠音、melody 复音砍到 2。真实管弦乐声部过一遍会被打残
  （小提琴 I 的双音、密集的十六分音符全没了）。导入的 MIDI 本身就是合法乐谱，
  没有「修复」可言。
  - **绕开而不是放宽**：放宽会改变所有 LLM 生成项目的行为，而绕开对现有实现是
    零改动。这是本设计的硬约束。
  - 仍保留渲染器真正依赖的钳制：velocity 夹到 1–127。

  **实现时推翻的一条**：设计原本还要「音高超出乐器音域就移八度」，那是照抄
  `score.py` 的规矩。用在这里是错的 —— 库里没有 bassoon，最接近的 `woodwind`
  是 55–93，而大管的真实音域是 34–75，照那个夹会把整个大管声部往上搬一个八度。
  真实总谱的音高按定义就是对的，**不夹**。这也是为什么音色号要和 `library_key`
  分开给（见下）。

### 声部映射：按总谱顺序，不读 GM 程序号

两份文件的圆号与小号都被 LilyPond 写成 **GM 69（英国管）**——没设
`midiInstrument` 时的默认值。轨道名也只是 `one:` `two:`。因此映射表按总谱顺序
写死在曲目清单里：

```
贝七：长笛 长笛2 双簧管 单簧管 大管 圆号 小号 定音鼓 小提琴I 小提琴II 中提琴 大提琴 低音提琴
埃格蒙特：（同族，14 轨，含两支长笛）
```

### 力度：源文件平的就反推，有的就原样用

判据：某轨 velocity **恒为一个值**才算「没有力度信息」。

判据原本写的是「不同取值数 ≤ 2」，实现后发现它会**随窗口长度翻脸**：埃格蒙特
缩到 28 小节后有 9 条轨只剩 101 与 127 两个值 —— 那正是谱面写的 f 与 ff，是真
力度。同一份文件截长了算「有」、截短了算「没写」，判据不该这样。

而且反推是**整首的决定，不是逐轨的**：平的声部占不到九成音符就一律不反推。
一半声部按谱面、一半按反推曲线缩放，同一小节里两组声部会按两套标准变响，
听起来是配器失衡而不是渐强。

- **埃格蒙特**：85 级 velocity（12–127），真实力度，**原样用，不反推**。
- **贝七**：全轨恒为 127。反推一条曲线：

  ```
  每小节 raw = Σ(在响的声部 × 配器权重) + 音符数 × 0.06
  配器权重：小号 1.7、定音鼓 1.6、圆号 1.5、小提琴I 1.2、双簧管 1.1、其余 1.0
  再做三小节移动平均，归一到 0.18–0.90
  ```

  配器权重不是拍脑袋：铜管与定音鼓的单位音量本来就大，这是配器法。移动平均是
  因为指挥做的是**乐句级**力度，逐小节抖动的曲线没法照着打。

  **验证**：反推结果必须重现这一乐章公认的形状（弦乐轻起 → 逐层加配器 → 全奏）。
  在 51–76 小节这个窗口上实测前 10 小节均值 **0.19** → 后 10 小节 **0.49**，
  整条曲线从 0.18 爬到 0.90，两处台阶正好落在第 67 小节木管进入与第 75 小节
  全奏处。若哪天改了权重或换了窗口导致曲线不再爬升，说明反推法不成立，
  不能拿去当评分真值 —— `self_check()` 里有这条断言（要求后 10 比前 10 高 0.15
  以上）。

  这条曲线**同时用于渲染**，不只是评分真值：只拿它当评分标准而音频是平的，
  等于让用户对着一段没有强弱的音乐做渐强。渲染时按小节缩放 velocity，并叠加
  `practice.py` 的 `_beat_accent`（M7k）恢复小节内的强弱层次，否则拍子听不出来
  ——那正是 M7k 量出来的问题：重音没有层次时四拍子和二拍子在耳朵里是一回事。

  力度是**推导的不是谱面的**，这一点要在界面上说明，不能让用户以为是贝多芬写的。

### 缓存键

沿用 `practice.piece_id` 的思路：`sha256(文件) + 截取窗口 + 算法版本` → id。
改了源文件或选段就是另一首，重复导入命中缓存不会堆出重复项目。

## 两个消费者

### 考试（`practice.py` + `exam.ts`）

`practice.py` 的 spec 增加「MIDI 来源」分支，产出与现有练习曲**同形**的
`(wav, mid, meta{grid, loudness_per_bar})`。渲染、缓存、`beat_grid`、前端
`PiecePlayer` / `PracticeRunner` 全部不改。

`exam.ts` 加一条曲目。rubric **含 `dynamicsMatch`**，真值就是上面那条反推曲线
——这是本设计选择反推而不是弃考力度的理由。权重给得比其他维度低
（`拍点准确度 .32 / 拍型准确度 .27 / 速度稳定性 .26 / 力度对应 .15`）：曲线是
推导的，不该占太大分量。

用户能拿到满分的前提是**音频与评分真值同源**——渲染时按同一条曲线缩放
velocity，所以用户听到的渐强就是被考的渐强，不存在「照着听到的打却被判错」。
界面上必须标明这条力度是**从配器推导**而非贝多芬写下的。

### 指挥体验（`project.py` + `FilePage`）

从 MIDI 造一个 project：每条 MIDI 轨 → 一个 instrument + 一条 take.wav。
现有的体感混音链路原样能用。

## UI

- **考试页**：`EXAM_PIECES` 本来就是卡片选择器，新曲目作为第 4 张进去。加来源
  徽标区分**真实乐曲**与**合成练习曲**——两者评分含义不同，不是装饰。
- **文件页**：「已有项目」上方加一块「内置曲目」，同样的卡片样式。点一下 →
  造项目 → 跳浏览页。已有项目一个都不动，纯增量。

## 验证

1. **三条渲染路各渲一次**，比对时长、RMS、首末非静音位置。三者应给出同样的
   时长与大体一致的能量包络（音色不同，RMS 允许差异，但不能出现某一路整段静音
   或长度对不上）。
2. `/api/practice/{id}/midi` 下载的必须是**原始未截取**的文件（sha256 与
   `assets/repertoire/` 里的一致）。
3. 力度反推的单调性断言（见上）。
4. 声部映射断言：每轨映射到的乐器音域能容纳该轨全部音高（移八度数量为 0 或极少）。
5. 现有链路回归：练习曲与三首合成考卷的 `piece_id` 不变、渲染结果不变。

## 明确不做

- **不支持任意 MIDI 上传。** 只接这两份随仓库分发、已知结构的文件。任意上传要
  处理速度图、拍号变更、声部识别、以及一个安全面（解析用户文件），是另一件事。
- **不支持多速度/多拍号。** 两段选段都不需要，真需要时再说。
- 不动 `validate_and_repair_part`，不动现有练习曲与考卷。
